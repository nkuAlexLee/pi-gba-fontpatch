# gba-text-translate LESSONS

> append-only；每条带日期 + ROM 名。recurring 模式（≥2 次）蒸馏进 SKILL.md 第六节。

## 2025-09-02 XTREME 首轮闭环

1. **子 agent 并行翻译丢控制码**：LLM 首轮约 7% 丢 [/n][/p]，门禁拦截后打包重试可达 100%。
   → 已被 {{C0}} 占位符流程机制性消除（#14 同源）。
2. **worker 超时**：glm-5.3-flash 400 条/批 30 分钟超时率约 40%（多为写完文件没来得及自检）。
   → 换 opencode-go/mimo-v2.5 + 「先写完文件再自检」指令。
3. **add 全表合并 bug**：旧版 add 把未扫到行标 conflict「原串已消失」——insert 之后再 add
   必然大规模误标。已改非破坏性；存量恢复：notes 含该标记且 mt 非空 → machine-translated。
4. **CSV 必须按 id 排序**：insert 重叠防御按 CSV 顺序判定，追加行不排序 = 大片误报重叠。
5. **apply id 大小写敏感**：translations.json 的 id 大小写必须与 CSV 一致，否则静默写 0 条。
6. **译文空格对齐**：worker 丢前导空格高发；游戏用"指向串内部（跳过空格）"的指针，
   空格错位 = 指针落进多字节中文码中间（症状：只显示后半字）。apply/insert 已内置对齐。

## 2025-09-03 EliteRedux 全量补翻（5111 条漏网）

7. **指针 dump 漏串的主因是运行时引用**：改版自定义文本大量不经指针表（运行时生成/内部偏移），
   指针引导 dump 只有 ~80% 覆盖；export-missing FF 锚点普查一次性找出 5111 条漏网
   （含 82 条菜单短串、576 条大段对话）。**新 ROM 必跑普查，不算可选步骤。**
8. **长对话批是 worker 失败重灾区**（三种病根，对应三种对策）：
   - 手拼 JSON 转义错 → 文件损坏。对策：强制脚本写文件（json.dump / JSON.stringify），
     prompt 明写「禁止手拼 JSON 字符串」
   - 每条 15-20 个 {{Cn}} 占位符时 mimo 指令遵循衰减（139/200 丢 token）。
     对策：★确定性配方——「按占位符切段 → 逐段翻译 → 同序连接回 zh」，
     实测 80/80 条 0 不一致（对比"保留占位符"指令的 139/200 失败）
   - 缩批：500（短句）/ 50→25（长对话）。批越小越稳。
9. **status=failed ≠ 产物失败**：worker 写完文件后进程异常收尾很常见（batch-08 报 failed
   实际 500/500 完美）。**先验产物文件（JSON 可解析 + 占位符一致 + 覆盖率）再决定重跑**，
   否则会白白重跑成功的批。
10. **治本方向（下次实现）**：占位符重组责任从模型移到代码——prepare 按 {{Cn}} 把 en 切成
    纯文本段，worker 只翻译无占位符的纯段，父级代码按原结构拼回。模型接触不到占位符 =
    机制性消除丢 token。分层模型：短句批 mimo，max_bytes>100 长对话批用强模型。
11. **菜单短串也会漏**：FIGHT/BAG/RUN/USE 等标志词精确扫描 82 条未译——菜单串多为
    内部偏移指针或词典型引用，主 dump 命中率低。菜单覆盖要用「标志词清单」专项审计。
12. **rebuild→insert→copy 铁律实例化**：roms/ 里的中文字库版 ROM 会过期（.s 改了没重新
    copy）。交付前必须 cmp er_full.gba vs roms/中文字库版，不一致就刷新。
