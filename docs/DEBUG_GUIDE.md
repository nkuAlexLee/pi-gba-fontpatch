# 字库破解调试功能使用指南

## 🎯 概述

本指南介绍如何使用集成到字库破解工具中的调试功能，这些功能基于 `console-test.html` 的实现，提供了实时监控和深度分析能力，大大增强了字库破解的效率。

## 🚀 快速开始

### 1. 打开调试版工具
- 访问 `font-cracker-debug.html`
- 或者从测试页面点击链接

### 2. 加载ROM
- 点击 **"载入ROM"** 按钮
- 选择 `testfiles/PokemonQuetzalAlpha7v0.gba` 或任意GBA ROM

### 3. 启用调试模式
- 点击 **"启用调试"** 按钮（状态变为 **"✅ 启用"**）
- 调试面板将显示实时信息

### 4. 开始破解
- 点击 **"开始破解"** 按钮
- 模拟器启动，字符捕获开始

## 🔧 调试功能详解

### 📊 寄存器实时监控

**位置**: 调试面板 → 寄存器标签

**显示内容**:
- **16个通用寄存器 (R0-R15)**: 32位十六进制值
- **状态标志位**:
  - **N** (Negative): 负数标志
  - **Z** (Zero): 零标志
  - **C** (Carry): 进位标志
  - **V** (Overflow): 溢出标志
  - **I** (IRQ disable): 中断禁用标志
  - **T** (Thumb state): Thumb模式标志

**辅助破解应用**:
1. **识别字符编码模式**:
   - 监控 R1 寄存器（字符编码存储）
   - ASCII字符: R1低8位有效 (0x20-0x7E)
   - 中文字符: R1双字节 (0x0100-0x1FF6)

2. **跟踪渲染流程**:
   - R15 (PC) 显示当前执行位置
   - R14 (LR) 显示返回地址
   - 结合Hook点地址分析调用链

### 💾 内存查看器

**位置**: 调试面板 → 内存标签

**功能**:
- 查看任意内存地址的内容
- 实时更新显示
- 支持跳转到指定地址

**辅助破解应用**:
1. **发现字符存储区域**:
   - 扫描ROM区域 (0x08000000-0x08800000)
   - 查找连续字符数据
   - 识别字库排列规律

2. **分析内存结构**:
   - 监控VRAM变化 (0x06000000)
   - 跟踪字符数据从ROM到VRAM的传输
   - 发现隐藏字符表

### ⚡ Hook点状态监控

**位置**: 调试面板 → Hook点标签

**显示内容**:
- GetGlyphWidth (0x080048EA): 单字符宽度计算
- GetStringWidth (0x08004CCC): 字符串宽度计算
- DrawGlyphTiles (0x08006876): 字符渲染绘制

**状态指示**:
- **✓ 激活**: Hook点已设置，正在监控
- **✗ 未激活**: Hook点未设置

**辅助破解应用**:
1. **验证Hook有效性**:
   - 确保所有关键Hook点都已激活
   - 监控Hook调用频率和时机

2. **发现新Hook点**:
   - 通过调试信息发现未记录的渲染函数
   - 扩展破解范围

### 📝 调试信息记录

**位置**: 调试面板 → 调试信息标签

**记录内容**:
- 每次Hook调用的时间戳
- 当前程序计数器 (PC)
- CPU寄存器状态快照
- 内存上下文信息
- 字符渲染详细信息

**辅助破解应用**:
1. **分析字符渲染模式**:
   - 记录每个字符的处理过程
   - 发现ASCII和中文的不同处理路径
   - 识别异常处理分支

2. **调试数据导出**:
   - 导出完整调试日志
   - 离线分析字符渲染过程

## 🔬 高级应用

### 1. 字符编码模式识别

通过监控寄存器变化，可以识别不同的字符编码处理模式：

```javascript
// 中文字符识别模式
if (R1_high_byte >= 0x01 && R1_high_byte <= 0x1E) {
    // 可能是中文字符首字节
    const second_byte = read_next_byte();
    const chinese_code = (R1_high_byte << 8) | second_byte;
    process_chinese_character(chinese_code);
}
```

### 2. 渲染函数调用链分析

通过PC和LR寄存器，可以重建字符渲染的调用链：

1. **GetGlyphWidth** 被调用 (PC = 0x080048EA)
2. 记录LR = 0x08004C00 (调用者地址)
3. 继续跟踪，发现调用链：
   - 0x08004C00 → GetStringWidth
   - 0x08004D00 → RenderText
   - 0x08004E00 → DisplayWindow

### 3. 字库结构推断

通过扫描内存，可以推断字库的组织结构：

```
0x08010000: 字库开始地址
0x08010000-0x08011000: ASCII字符 (128字节/字符)
0x08011000-0x08020000: 中文字符 (128字节/字符)
0x08020000: 标点符号
```

## 🛠️ 故障排除

### 问题1: 调试面板不显示
**可能原因**:
- 未加载fontcracker-debug.js
- CSS样式未正确应用

**解决方案**:
- 检查浏览器控制台错误
- 确保所有脚本文件正确加载

### 问题2: 寄存器值不更新
**可能原因**:
- 模拟器未运行
- 调试模式未启用

**解决方案**:
- 确保点击了"开始破解"
- 确认调试模式已启用

### 问题3: 内存读取错误
**可能原因**:
- 地址无效或未映射
- 内存保护

**解决方案**:
- 使用有效的GBA内存地址 (0x08000000-0x0E000000)
- 避免系统保留区域
