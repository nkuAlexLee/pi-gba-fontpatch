# 字库破解调试功能演示脚本

## 🎬 演示概述
展示如何使用调试功能增强字库破解过程，从基本字符捕获到深度分析。

## 📋 演示准备
1. **工具**: 打开 `font-cracker-debug.html`
2. **测试ROM**: `testfiles/PokemonQuetzalAlpha7v0.gba`
3. **录制软件**: OBS Studio 或类似工具

## 🎮 演示流程

### 场景1: 基础破解演示 (2分钟)

#### 步骤1: 加载ROM
- 点击 **"载入ROM"** 按钮
- 选择测试ROM文件
- 观察进度条变化
- 显示 **"ROM已载入 ✅"**

#### 步骤2: 启动破解
- 点击 **"开始破解"** 按钮
- 模拟器启动，游戏运行
- 实时显示捕获的字符
- 等待 **"NEW GAME"** 出现

#### 步骤3: 基础分析
- 显示字符网格中的ASCII字符
- 展示统计信息 (捕获总数、ASCII计数)
- 导出基础JSON数据

### 场景2: 调试功能演示 (3分钟)

#### 步骤1: 启用调试模式
- 点击 **"启用调试"** 按钮
- 状态变为 **"✅ 启用"**
- 调试面板开始实时更新

#### 步骤2: 寄存器分析
- 切换到 **"寄存器"** 标签
- 观察R0-R15寄存器实时变化
- 重点展示:
  - **R0**: 窗口指针变化
  - **R1**: 字符编码 (ASCII vs 中文)
  - **R15 (PC)**: 执行流程跟踪

#### 步骤3: 内存查看
- 切换到 **"内存"** 标签
- 输入ROM地址: `0x08000000`
- 展示内存内容的十六进制和ASCII显示
- 跳转到VRAM地址: `0x06000000`

#### 步骤4: Hook点监控
- 切换到 **"Hook点"** 标签
- 显示三个Hook点的激活状态
- 演示Hook点触发时的调试日志

### 场景3: 深度分析演示 (4分钟)

#### 步骤1: 内存扫描
- 点击 **"扫描"** 按钮
- 展示扫描进度
- 显示发现的文本区域和数量
- 分析扫描结果摘要

#### 步骤2: 单步执行分析
- 点击 **"单步"** 按钮
- 逐帧分析字符渲染
- 观察每条指令后的寄存器变化
- 解释CPU处理流程

#### 步骤3: 中文字符识别
- 定位到中文文本显示场景
- 监控R1寄存器的双字节编码
- 记录中文字符的完整处理流程
- 分析内存中的字库存储结构

#### 步骤4: 数据导出分析
- 点击 **"导出"** 按钮
- 下载包含调试信息的JSON文件
- 展示导出数据的结构
- 解释调试信息如何辅助破解

### 场景4: 实战破解演示 (5分钟)

#### 步骤1: 完整破解流程
- 从ROM加载到字符捕获
- 启用调试模式监控整个过程
- 展示实时分析能力

#### 步骤2: 问题诊断
- 模拟字符识别错误
- 使用调试功能定位问题
- 分析寄存器状态和内存内容
- 演示问题解决过程

#### 步骤3: 效率对比
- 对比启用调试前后的破解效率
- 展示调试信息如何减少人工分析时间
- 说明准确性的提升

#### 步骤4: 结果展示
- 显示完整破解的字库数据
- 展示字符编码映射表
- 验证破解结果的准确性

### 场景1解说
```
首先，我们加载一个测试ROM。点击"载入ROM"按钮，选择文件。
ROM加载完成后，我们可以看到状态变为"已载入"。
现在点击"开始破解"，模拟器启动，游戏开始运行。
我们可以看到字符被实时捕获，很快就能看到"NEW GAME"出现在日志中。
这是基础破解流程的展示。
```

### 场景2解说
```
接下来，我们启用调试功能。点击"启用调试"按钮，
现在调试面板开始实时更新。
切换到寄存器标签，我们可以看到CPU的所有寄存器状态。
注意R1寄存器，这里存储了字符编码。当ASCII字符显示时，R1是单字节编码；
当中文字符出现时，R1会显示双字节编码。
这是调试功能的核心价值之一：实时监控CPU处理字符的过程。
```

### 场景3解说
```
现在让我们深入分析。切换到内存标签，我们可以查看任意地址的内存内容。
输入ROM开始地址，可以看到游戏的代码和字库数据。
扫描内存可以发现隐藏的文本区域。
单步执行让我们可以逐条分析指令，理解字符渲染的每个步骤。
这对于理解复杂的字符处理算法非常有用。
```

最后，我们演示完整的破解流程。从ROM加载到最终的字库提取，

监控内存变化、跟踪执行流程，一步步完成字库破解。
